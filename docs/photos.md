# 사진 관리

## 사용 방법

1. 측면 **사진 대상 폴더**에서 드라이브를 열고 원하는 폴더를 등록합니다. 파일 색인·SMB와 별도 목록이며, 어느 쪽의 등록·해제도 다른 목록을 바꾸지 않습니다.
2. 등록 즉시 사진 작업이 시작됩니다. 이후 10분마다 변경을 확인합니다. 개요와 사진 관리 화면의 진행 상태는 5초마다 자동 갱신됩니다. `지금 색인`으로 즉시 요청하거나 일시정지한 작업을 재개합니다.
3. **사진 관리**에서 촬영 월별 보관함, 기존 폴더별 앨범, 주제, 사진/영상/Live Photo, 촬영 시간 범위 안/밖을 선택합니다. 날짜 경계는 포함하며, 입력은 브라우저 현지 시간입니다.
4. **사람들**에서 얼굴 묶음의 이름을 저장하고 해당 사람이 있는 사진을 엽니다. 상세 화면의 얼굴 묶음 수정으로 다른 사람에게 이동하거나 새 사람으로 분리합니다. 주제 역시 여러 개를 직접 선택하거나 자동 분류로 복원할 수 있습니다.
5. 등록 해제는 색인·얼굴 연결·사진 썸네일만 정리합니다. 원본은 수정하거나 삭제하지 않습니다. 드라이브가 없어도 해제할 수 있습니다.

## 저장과 경계

`photo_roots`는 외장 볼륨 UUID와 상대 폴더를 저장합니다. 마운트명이 달라져도 같은 폴더를 찾습니다. `roots` 및 SMB 상태와 분리됩니다. 외장 USB/PCIe 파일시스템만 등록할 수 있습니다. `externalNodes` 등 제외 이름은 디렉터리에 진입하기 전에 걸러집니다. 숨김 항목·심볼릭 링크는 색인하지 않습니다. 모든 사진 API, 원본, 썸네일, 동영상은 기존 ID/PW 세션 인증을 사용하고 변경 요청에는 CSRF 검증이 적용됩니다.

`photos`에 상대 파일명, 폴더 앨범, 촬영 시각과 출처, 원본 크기/수정 시각, 모델 점수와 주제, 사용자 수정값을 저장합니다. `photo_people`의 얼굴 특징과 이름, `photo_faces`의 사진 연결은 Pi의 비공개 DB에만 있습니다. 사진이나 얼굴 특징을 외부 추론 서비스로 전송하지 않습니다. 모델 최초 설치만 공식 공개 배포 서버에서 내려받습니다.

## 메타데이터와 Live Photo

ExifTool의 DateTimeOriginal, CreateDate, OffsetTimeOriginal을 사용합니다. 시간대가 없는 메타데이터는 Pi 현지 시간으로 해석하며 출처에 표시합니다. 촬영 정보가 없으면 수정일로 대체합니다. iCloud의 별도 데이터베이스나 편집 앨범을 가져오는 기능은 없으며, 실제 디렉터리가 앨범입니다.

Apple ContentIdentifier/MediaGroupUUID 일치를 우선합니다. 없으면 같은 폴더·같은 기본 파일명·5초 이내 촬영 시각의 사진/영상을 **추정 연결**하고 상세 화면에 명시합니다. 식별자가 맞는 실제 Apple 기기 원본에 대한 검증은 별도로 필요합니다. 연결 영상은 보관함에서 중복 표시하지 않습니다. Live Photo의 정지 사진과 영상의 10%, 50%, 90% 지점을 함께 분류합니다. 일반 영상도 세 지점을 표본 처리하므로 모든 등장인물·물체를 빠짐없이 찾는 방식은 아닙니다.

JPEG/PNG/WebP/TIFF/HEIC/HEIF 등의 사진을 표시합니다. H.264 및 호환 오디오의 MP4는 HTTP Range를 지원하는 원본 스트림, HEVC MP4나 MOV 등은 기존 H.264 프록시를 사용합니다. 프록시 제한은 최대 10분·원본 2GiB이며 큰 원본은 다운로드가 필요합니다. 원본 파일은 변환하지 않습니다.

## 모델과 정확도

- 주제: OpenAI CLIP ViT-B/32의 Xenova ONNX FP32 변환과 주제별 여러 문장 비교. 사람·동물·건물·서류·카드·음식·자연을 각각 독립적인 텍스트 대조 점수로 판정합니다. 건물 0.65, 일반 주제 0.70, 문서와 혼동하기 쉬운 카드 0.82 기준입니다. 점수는 보정된 정확도/확률이 아닙니다. 카드 번호나 문서 내용을 읽거나 저장하지 않습니다.
- 얼굴: OpenCV Zoo YuNet 2023mar 검출(신뢰도 0.87, 최소 얼굴 24px) + SFace 2021dec 특징. 특징 코사인 유사도 0.55 이상이면 기존 대표 얼굴에 묶습니다. 이름은 사용자가 입력합니다. 작은 얼굴, 옆얼굴, 가림, 나이 변화, 비슷한 얼굴에서 누락·오분류가 생길 수 있습니다. 자동 결과를 신원 인증에 사용하지 않습니다.
- 원본이 바뀌면 다시 분류하며 수동 주제는 유지합니다. 얼굴 연결은 해당 사진 재처리 시 다시 계산됩니다. 단순 재검사에서는 기존 결과를 재사용합니다. 파일 이동은 새 항목으로 처리합니다.
- 사전학습 모델만 사용하며 PC GPU 학습은 하지 않습니다. 다운로드 리비전과 SHA256은 `scripts/install-photo-models.py`에 고정했습니다.

출처: [CLIP 원본](https://huggingface.co/openai/clip-vit-base-patch32), [ONNX 변환](https://huggingface.co/Xenova/clip-vit-base-patch32), [OpenCV 얼굴 검출·인식](https://docs.opencv.org/4.13.0/d0/dd4/tutorial_dnn_face.html). CLIP 원본 MIT, YuNet MIT, SFace Apache-2.0 고지는 각 배포 저장소를 참조합니다. 가중치를 이 GPL 저장소에 재배포하지 않습니다.

## 운영

`alter-photos.service`는 CPU 1코어 상당, 메모리 1200MiB, swap 128MiB, 낮은 우선순위로 동작합니다. 최대128개 분류마다 자식 프로세스를 종료해 모델 메모리를 반환하고 DB에서 다음 미완료 항목을 이어받습니다. 일시정지는 현재 작업 경계에서 반영됩니다. 비정상 종료 후 기존 항목은 보존되고 다음 스캔이 미완료 항목을 다시 처리합니다. 오프라인/읽기 실패 폴더는 기존 목록을 지우지 않습니다. 재부팅 복구와 루트 실행파일에도 사진 서비스를 포함합니다.

개요의 CPU/RAM은 시스템 전체 사용률입니다. GPU 수치를 제공하지 않는 Pi 드라이버는 **계측 미지원**으로 표시합니다. CPU에서 실행되는 모델의 GPU 사용률을 임의로 0%라고 보고하지 않습니다.

## API

모든 경로는 `/api/photos` 아래입니다.

| 경로 | 입출력 / 동작 |
|---|---|
| GET/POST roots | 사진 전용 목록 / `{path}` 등록 |
| DELETE roots/{id} | 오프라인도 해제, 원본 보존 |
| POST scan, pause | 작업 요청·재개 / 일시정지 |
| GET status | 단계, 발견/처리/대상/오류 수, worker 상태, 주제 이름 |
| GET albums, people | 폴더 앨범 / 얼굴 묶음과 이름 |
| GET items | root, album, topic, person, after/before(epoch), exclude, kind, q, offset; 120개 단위 |
| PATCH items/{id} | `{labels:[...]}` 수동 주제, null이면 자동값 복원 |
| PATCH people/{id} | `{name}` 이름 저장 |
| PATCH faces/{id} | `{person:id}` 이동, 0이면 새 묶음 |
| GET faces/{id}/thumbnail | 인증된 개별 얼굴 미리보기 |
| GET items/{id}/thumbnail | 인증된 JPEG 썸네일 |
| GET items/{id}/media | inline 이미지/영상; live=true 연결 영상, original=true 원본 다운로드 |

`tests/test_photos.py`는 격리된 임시 폴더/DB로 경계·독립성·재마운트·날짜·수정·Live 연결을 확인합니다. `tests/live_photos.py`는 별도 `Alter-Photo-Verification-*` 폴더만 만들고 공개 인물 샘플/합성 문서/합성 영상으로 실제 모델과 API를 검증합니다. 사용자 사진 라이브러리를 자동 선택하지 않습니다. 검증 폴더 식별자는 비공개 `data/photo-verification.json`에 남으며 확인 후 해당 시험 폴더만 제거합니다.

## 사진 대화 검색과 처리 개선 (2026-10-24)

대화에서 “건물이 나온 사진을 찾아줘”, “지난달 사람 사진”, “이름이 나온 사진을 찾아줘”를 사용할 수 있습니다. 이름은 **사람들**에 사용자가 저장한 이름과 일치해야 합니다. 로컬 언어 모델은 요청을 주제·사람 이름·촬영 날짜 조건으로 해석하고, 서버가 사진 DB를 조회해 전체 일치 수와 최대 8개 미리보기 카드를 반환합니다. 원본 이미지를 언어 모델에 넣어 자유로운 시각 추론을 하는 기능은 아닙니다. 동물 등의 세부 종류는 상위 주제 검색이며 정확한 개체 검색을 보장하지 않습니다. 얼굴 이름이 모호하거나 등록되지 않았다면 안내하고 신원을 추측하지 않습니다. 사진/영상 보관함은 일반 파일 색인과 계속 분리됩니다.

ExifTool은 해시가 달라진 파일에만 명시적인 단일 경로로 호출합니다. 디렉터리 탐색과 파일 처리 완료 위치를 DB 큐에 저장하므로 재시작 후 완료 위치부터 진행합니다. 해시가 같으면 기존 촬영 정보·주제·얼굴을 유지합니다. 모델 버전이 다르면 해당 자동 결과를 재계산하며 수동 주제와 사람 이름은 유지합니다.

진행률은 DB state.photo_progress에, 파일별 상태는 photos/scan_entries에 저장합니다. heartbeat만 별도 파일입니다. 파일 색인의 전체 FTS 교체를 없애고 작은 DB 쓰기 트랜잭션을 사용합니다. 작업 중단 항목은 5분부터 증가하는 지연(최대24시간) 후 재시도하고 일반 오류는1시간 후 재시도합니다. 이미지 메모리를 제한하고 고정 CLIP 주제 문장 특징을 캐시합니다.


개요의 CPU 온도는 Linux thermal 센서의 실제 섭씨 값입니다. RAM은 독립 DIMM/DRAM 센서가 노출될 때만 표시합니다. 현재 Pi 5에서는 RAM 온도 센서가 없어 **RAM 온도 센서 없음**으로 표시합니다. CPU 온도로 RAM 온도를 대신하지 않습니다.

### 단계별 진행률

색인 전 등록 폴더의 미디어 파일 수를 먼저 집계합니다. 개요와 사진 화면은 파일 정보 확인 단계의 확인 수/발견 전체 수와 ETA, 이후 주제·얼굴 분류 단계의 기존 완료 포함 처리 수/Live Photo 중복 제외 전체 수와 ETA를 표시합니다. ETA는 현재 단계의 측정 평균이며 영상 길이/모델 초기화/동시 작업에 따라 달라집니다. 집계 중·초기 표본 부족·중단·오류에는 확정 ETA를 표시하지 않습니다. 자세한 분모 정의는 운영 문서의 색인 진행률과 ETA 항목을 참조하세요.
