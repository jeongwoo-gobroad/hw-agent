# DB 기반 증분 색인과 접속 보호

## 색인 판단과 재시작

파일과 사진 모두 볼륨 UUID + 등록 폴더의 상대경로를 기준으로 유지합니다. SQLite WAL 트랜잭션이 결과와 작업 완료 표시를 함께 저장합니다.

1. `scan_dirs`에서 미완료 디렉터리만 열고 파일 목록을 `scan_entries`에 256개 이하 배치로 기록합니다. 완료한 디렉터리는 재시작 후 다시 열지 않습니다. 중단 순간 처리하던 디렉터리는 재열거할 수 있으나 UNIQUE 키로 중복을 막습니다.
2. 파일 크기, mtime_ns, ctime_ns를 비교합니다. 같고 최근 3일 이내 해시가 있으면 원문을 읽지 않습니다. 변경·해시 없음·3일 경과 시 SHA-256을 1MiB씩 읽어 계산합니다. 읽기 전후 stat이 바뀌면 완료로 저장하지 않습니다.
3. 해시가 같고 추출기/분류기 버전도 같으면 기존 텍스트, 검색 토큰, 촬영 정보, 주제와 얼굴 연결을 재사용합니다. 시간만 바뀌고 내용이 같아도 재추출하지 않습니다. 모델 버전 변경은 해당 자동 분류만 다시 계산합니다.
4. 파일 결과/FTS와 완료 표시는 같은 트랜잭션입니다. 사진 메타데이터 완료와 모델 분류 완료는 별개이며 `analysis_version`, `scores`, `retry_after`, `attempts`로 추적합니다. 성공한 사진 분류는 즉시 커밋합니다.
5. 등록 폴더 확인이 끝나고 드라이브가 연결되어 있을 때만 사라진 항목을 DB에서 정리합니다. 원본 파일을 지우지 않습니다. 오프라인/읽기 실패 시 기존 색인을 보존합니다. 특정 파일 읽기 실패는 오류로 기록하고 다음 항목으로 진행하며 다음 주기에서 재시도합니다.

완료 후 10분이 지나면 다음 변경 검사를 시작합니다. 재시작해도 진행 중인 큐는 버리지 않습니다. 3일은 **전체 추출/분류를 초기화하는 주기**가 아니라 **해시 검증 유효기간**입니다. 내용 변경을 파일시스템 메타데이터만으로 알아차리지 못한 경우도 다음 해시 검사에서 감지할 수 있습니다. 새 파일/이동된 파일은 새 항목이며, 다른 경로의 동일 파일까지 통합하는 전역 중복 제거는 제공하지 않습니다.

처음 이전 DB를 이관할 때는 해시가 없으므로 기준 해시를 한 번 생성합니다. 기존 크기/수정 시간이 같으면 저장된 추출·분류 결과를 우선 보존합니다. 당시의 원문 해시는 없으므로 과거 내용을 암호학적으로 증명할 수는 없습니다. 기존 staging 결과도 버리지 않고 일치하는 항목의 추출 캐시로 소비합니다. 기준 해시 생성은 큰 드라이브에서 수 시간 이상 걸릴 수 있으며 진행 중에도 기존 검색 결과는 사용할 수 있습니다.

## DB와 진행률

| 저장 위치 | 역할 |
|---|---|
| scan_jobs | 종류·루트·작업 세대·단계·발견/완료/재사용/변경/오류 수 |
| scan_dirs / scan_entries | 디렉터리와 파일의 미완료 큐 |
| files | 정밀 stat, content_hash/hash_checked, extractor_version, 텍스트 |
| photos | 정밀 stat/해시, EXIF, analysis_version, 재시도, 자동/수동 주제 |
| photo_faces / photo_people | 완료한 얼굴 연결·대표 특징·사용자 이름 |
| state.photo_progress | 사진 단계, 분모/분자, ETA의 표시용 최신 상태 |

파일 카드의 진행률 원본은 scan_jobs이며 메모리 상태는 표시용입니다. 사진의 진행률은 DB에 저장하고 heartbeat만 파일로 유지합니다. 재시작 직후 ETA는 새 처리 속도를 측정할 때까지 계산 중으로 표시합니다. 디렉터리 집계 중에는 최종 분모를 확정하지 않습니다. 일부 루트를 먼저 처리하는 동안 나머지 루트의 집계가 끝나지 않았으면 현재 발견 수만 표시하고 전체 백분율/ETA는 보류합니다. 오류 재시도 대기와 완료는 구분합니다.

사진 분류는 한 자식 프로세스당 최대128개로 제한하고 종료해 모델 메모리를 반환합니다. 고정 CLIP 주제 문장은 최초 배치4로 계산한 뒤 모델 버전/문장 해시별 특징 캐시를 재사용합니다. JPEG는 디코더의 축소 기능을 적용한 후 최대1920px로 처리합니다. 미완료 상태에서 자식이 중단되면 그 항목은5분부터 최대24시간까지 지연 재시도하며 다른 항목을 진행합니다. 일반 처리 오류는1시간 뒤 재시도합니다. 모든 입력 크기·코덱에서 OOM이 불가능하다는 보장은 없습니다.

## 접속 경계

| 진입점 | 접근 범위 | 로그인 |
|---|---|---|
| 11977 | 127.0.0.1 및192.168.0.0/24 | ID/PW, 실패 차단 |
| 8080 | 포트포워딩용 HTTP, 기존 ngrok | ID/PW + 매번 일회용 CAPTCHA, 실패 차단 |
| 18080 | Pi loopback만 | nginx 뒤 단일 앱, 직접 외부 접속 불가 |

nginx가 X-Alter-Exposure를 덮어쓰므로 클라이언트가 내부용이라고 주장해도 외부 CAPTCHA를 끌 수 없습니다. 외부의 전달 IP 헤더는 무시하며 로컬 ngrok에서 온 요청만 실제 접속 IP 전달을 신뢰합니다. 내부/외부는 쿠키 이름과 DB session scope를 분리합니다. 같은 호스트의 서로 다른 포트로 쿠키가 전달되어도 내부 세션으로 외부 API를 열 수 없습니다. OAuth의 ticket/state 검증은 기존 그대로입니다.

공유기에는 **8080만** 전달하세요.11977/18080/8081/8082를 포워딩하지 않습니다. 공인IP/DDNS 호스트는 `.env`의 ALLOWED_HOSTS에 명시해야 하며 공유기 NAT 설정은 별도입니다. HTTP는 전송을 암호화하지 않습니다. 기존 ngrok HTTPS도 유지되지만 운영/브라우저 검증은11977을 사용합니다.

## 설정과 API

설정 화면의 접속·보안에서 다음 값을 저장합니다. 값은 DB에 저장되고 다음 시도부터 적용합니다. 진행 중인 차단의 종료 시각은 정책을 바꿔도 유지합니다.

| 필드 | 기본 | 허용 범위 |
|---|---|---|
| max_failures | 5회 | 1~20회 |
| window_minutes | 10분 | 1~60분 |
| block_minutes | 10분 | 1~1440분 |

`GET /api/settings/security`로 조회, `PUT`으로 위 세 정수를 저장합니다. 인증·CSRF 검증을 통과해야 합니다. 실패 횟수는 IP/진입점별 HMAC 키에 저장합니다. 같은 공인IP를 공유하는 사용자는 외부 차단을 공유할 수 있습니다. 차단 응답은429와 Retry-After 초를 반환합니다. 계정 전체를 잠그지 않습니다.

`GET /api/login/challenge`: 내부는 required=false, 외부는 required/id/image(data PNG)/expires_in을 반환합니다. 답은 반환하지 않으며 HMAC만 DB에 저장합니다. 6자, 3분 유효, IP 바인딩, 한 번 제출 후 폐기합니다. 새 이미지 요청은 초당1회이며 이전 이미지는 무효화됩니다. 잘못된 보안 문자도 실패 횟수에 포함합니다.

`POST /api/login`의 외부 입력은 username/password/challenge_id/captcha입니다. 내부는 username/password입니다. 자동화용 외부 CAPTCHA 우회 API는 없습니다. 외부 live_external/live_stream 스크립트는 사람이 확인한 ALTER_CAPTCHA_ID/ALTER_CAPTCHA_ANSWER를 환경으로 전달할 수 있습니다. 일반 검증은11977을 사용합니다.

## 배포·검증·복구

DB 마이그레이션 전 alter/alter-photos를 중지하고 WAL 체크포인트/SQLite backup을 수행합니다. DB/data/.env/models는 Git에서 제외합니다. 앱 업데이트는 스키마 추가 방식이며 기존 색인을 비우지 않습니다. `scripts/install-web-entrypoints.sh`로 nginx, `scripts/install-startup.sh`로 서비스들을 설치합니다. start.sh는 nginx도 복구합니다.

`tests/test_resumable.py`: 무변경 skip, 같은 해시, 동일 크기 변경, 이전 staging, 얼굴/주제 유지와 무효화, 버전/진행률 저장. `tests/test_process_resume.py`: 실제 별도 프로세스를 항목 커밋 직후 즉시 종료하고 다음 프로세스에서 재개. `tests/test_login_security.py`: CAPTCHA 재사용/만료/IP 바인딩, DB 차단, 설정 검증/CSRF, 세션 분리. `scripts/verify-photo-runtime.py`: 사용자 미디어를 열지 않고 설치된 실제 모델을 합성 이미지로 실행합니다.

전원 코드를 직접 뽑는 물리 시험은 하지 않았습니다. SQLite 커밋 이전의 진행 중인 한 항목은 다시 처리될 수 있으며, 저장장치/전원 하드웨어 손상은 별도의 백업이 필요합니다. 금지 이름은 디렉터리에 진입하거나 stat하기 전에 거르며 해당 경로는 진단에도 사용하지 않습니다.
