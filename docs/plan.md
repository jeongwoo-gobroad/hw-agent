# 구현 순서와 완료 조건

## P0 — 조사·설계

SSH 하드웨어 조사, README, 에이전트 안내, 요구사항/인수 기준, 라이브러리 후보, GPL 공개 저장소.
이번 작업의 산출물이다. 앱 배포 완료와 구분한다.

## P1 — 운영 가능한 기반

FastAPI 구성, 인증/CSRF, SQLite migration, 장치 목록과 허용 루트,
systemd, 로그 마스킹, `.env` 검증, 백업·배포 스크립트를 구현한다.
Pi 서버와 Windows Chrome에서 인증 경계 및 USB 표시를 검증한다.

## P2 — 파일과 공유

추출 worker/FTS5/변경 감시/72시간 세대 교체, 검색 UI, HEIF/MOV 프리뷰,
권한 제한 Samba 헬퍼를 구현한다. 테스트 USB 기존 자료와 분리된 표본 폴더를 사용한다.

## P3 — 카메라·화면

Picamera2 스트림/분할 녹화, 실제 디스플레이 터치 UI, MediaPipe 호환 환경과
다섯 제스처 인식을 검증한다. LLM보다 먼저 상시 기능의 메모리 예산을 측정한다.

## P4 — 한국어 모델과 대화

최신 후보/한국어 특화 후보 비교, GGUF 실행기와 자원 한도, 대화 저장과
검색 도구·카드를 구현한다. 실제 동시부하와 한국어 평가로 모델을 확정한다.

## P5 — SmartThings·Flow

사용자 계정 OAuth 등록 정보 또는 초기 PAT 확보 후 기기 연결,
Flow 편집/실행 이력, 채팅/제스처 매핑을 구현한다.
외부 자격증명이 없는 상태에서 실제 제어 성공을 주장하지 않는다.

## P6 — 마이크 확장

USB/GPIO 마이크 확보 후 호출어·한국어 STT·명령 파이프라인을 추가한다.
GPIO 마이크는 하드웨어 드라이버와 ALSA 인식부터 검증한다.

## 배포마다 수행

관련 인수 기준 → 비밀정보 검사 → 문서 상태 수정 → commit/push →
Pi 소스 동기화 → 서비스 smoke test. 자동화가 실제 설치되기 전까지
“앞으로 모든 업데이트가 자동 푸시된다”고 표현하지 않는다.
